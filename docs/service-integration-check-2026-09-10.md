# 실제 서비스 연동 점검 — 2026-09-10

대상: 로컬 Docker 서비스 `http://localhost:3001`. Chrome/Playwright에서 임시 계정으로 실제 API를 호출했다. 실행 후 생성한 계정을 삭제했다. 백엔드 전체 테스트는 서비스 DB와 분리한 임시 PostgreSQL·Redis에서 실행했다.

## 재현하고 수정한 오류

- 샘플 매물 추천 버튼이 HTTP 500을 반환했다. 라우터가 필수 필드 `PropertyQuery.intent`를 누락했고, 화면의 한글 투자 목적과 내부 스키마 값도 일치하지 않았다. 의도 필드를 전달하고 한글 목적을 내부 값으로 변환했다. 잘못된 목적·예산 범위 등은 요청 검증에서 422로 거절한다.
- 추천 화면에서 `2.5억`을 25억으로 전송하던 문자열 변환을 수정했다. 소수·복합 단위를 원으로 환산하고 잘못된 예산 입력은 화면에서 안내한다. 실제 Docker 화면에서 `2.5억`이 `250000000`원으로 전송되는 것을 확인했다.

## 실제 브라우저에서 확인한 범위

| 기능 | 확인 결과 |
| --- | --- |
| 지역 탐색 | 화면 로드·지역 API 200. 시·도 목록은 현재 1개만 반환 |
| 실거래 단지 추천 | 서초구 검색 API 200, 결과 5개 및 단지명 화면 표시 |
| 샘플 매물 추천 | 투자 목적·최소 예산 2.5억 요청 200, 결과 5개, 내부 목적 investment 확인 |
| AVM | 후보 주소·84.9㎡ 자동 채움 → 실제 모델 실행 → 작업 done → 원 단위 변환 → 후보 저장 → 새로고침 후 유지 |
| 자금 시뮬레이션 | 후보 가격 자동 채움 → 실제 계산 저장 → 비교 화면 자금 경고 → 저장 조건 복원 → 재계산 경고 해제 → 가격 변경 시 재검토 |

AVM은 폼 진입 경로 1건을 실제 실행했다. 모든 유형·지역의 시세 정확도나 채팅 도구 경로 전체를 이번 실행으로 검증한 것은 아니다. 샘플 추천은 개발용 가상 매물이다. 지역 탐색의 데이터 범위는 추가 시딩·점검이 필요하다.

## 회귀 검증과 실행 방법

- 백엔드: 816개 통과.
- 오프라인 평가: 고정·가상 입력 33개 통과. 실제 대화 품질·실거래 추정 정확도 평가와 구분한다.
- 프론트엔드: 타입 검사·린트·프로덕션 빌드 통과. 금액 변환 Node 테스트 2개 통과.
- Docker 프론트엔드 재빌드 후 검색·자금 브라우저 검증 통과.

`scripts/verify_search_browser.cjs`, `scripts/verify_candidate_avm_browser.cjs --form`, `scripts/verify_candidate_funding_browser.cjs`를 Node로 실행한다. Chrome 및 Playwright가 필요하며, `PLAYWRIGHT_MODULE_PATH`로 Playwright 모듈 경로, `E2E_BASE_URL`로 서비스 주소를 지정할 수 있다. AVM 검증은 실제 모델·외부 데이터 호출과 수분의 실행 시간이 필요하다.

금액 변환 테스트: `node --test web/tests/moneyInput.test.mjs` (확인 환경 Node 24.12).

## 추가: 컨시어지 모델 출력 검증

`transaction_type: null`을 반환한 실제 안내 질문이 의도 분석 오류로 처리되는 것을 재현했다. 모델 추출 봉투와 실행 조건을 분리하고, 거래 유형 미입력을 매수로 가정하지 않도록 변경했다.

- 필드별 엄격 검증·명시적인 한글 별칭 변환. 잘못된 값은 조건 확인 안내 후 도구 실행을 중단한다.
- 부분 응답의 누락·null은 이전 조건을 유지한다. 지역명 변경 시 이전 코드를 제거하고 법정동 마스터로 확인한다.
- `예산 제한 없애줘` 같은 명시적인 단독 삭제 명령만 조건을 해제한다. 부정문·인용된 질문·모델 단독 삭제 지시는 해제하지 않는다. 복합 문장 삭제 표현의 폭넓은 이해는 별도 개선 대상이다.
- 일반 사용 안내는 추가 설명 모델 호출 없이 제공한다. 지역 검색에는 거래 유형을 확인하며 전월세 요청을 매매 데이터로 처리하지 않는다.

검증: 추가 회귀 사례 25개를 포함해 백엔드 841개 통과, 오프라인 평가 33개 통과, 프론트엔드 타입 검사·린트·빌드 통과. 실제 브라우저의 동일 안내 질문은 8.19초 후 HTTP 200 / status=completed로 정상 답변을 표시했고, 임시 계정은 삭제했다. 로컬 개발 API의 소스 마운트·재시작으로 변경사항이 반영됐다.

이번 변경은 모델 출력 검증 범위다. 프록시의 30초 제한, 장시간 작업 처리, 나머지 컨시어지 도구 연결은 해결하지 않았다. 유효한 숫자로 출력된 금액이 사용자 발화와 의미상 일치하는지 검증하는 기능도 별도 과제다.
