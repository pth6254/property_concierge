## 컨시어지 추천·자금·후보 비교

<a id="concierge-사용-흐름"></a>

### 사용 흐름

로그인 후 AI 컨시어지에서 케이스와 후보를 선택한다.

1. “이 후보 자금 분석해줘. 보유 현금은 3억이고 대출 비율은 50%야.”
2. 필요한 추가 조건을 안내받고 “금리 연 4%, 30년 원리금균등, 취득 후 1주택, 비조정지역, 기존 대출 없음, 연소득 1억, 월 상환 한도 200만원”처럼 보완한다.
3. “그럼 금리만 5%로 바꿔서 다시 계산해줘”로 이전 조건을 유지하며 재계산한다.
4. “후보 비교해줘”로 케이스의 저장된 후보를 비교한다. 비교는 후보를 개별 선택하지 않아도 실행된다.

금융 조건과 계산 결과는 채팅에 표시되며, 케이스 화면 링크로 상세 검토를 이어갈 수 있다. 최종 후보 선택이나 거래 결정은 자동 변경하지 않는다.

<a id="concierge-단지-추천과-후보-연결"></a>

### 단지 추천과 후보 연결

`select_properties`는 시·군·구 또는 법정동의 최근 12개월 해제 제외 아파트 매매 실거래에서
최대 5개 단지를 안내한다. 실제 활성 매물이나 호가를 검색하는 도구는 아니다.
지역·아파트·매매 조건이 부족하면 보완을 안내한다. 대화의 지역·예산·최소 면적을 유지하며
예산 상한을 시점수정 단지 평균 가격에 적용한다. 최소 면적은 개별 거래 하한이다.
추천 결과 설명은 결정론적 문장으로 제공하며 답변 작성용 모델을 추가 호출하지 않는다.

카드에서 실제 검토 주소·전용면적을 확인해 후보를 저장한다. 평균 면적을 입력값으로 복사하거나
평균 실거래가를 호가로 저장하지 않는다. 희망가를 모르면 누락 정보로 안내한다.
같은 케이스의 이름·주소·면적·유형이 일치하는 기존 후보는 재선택하지만 여러 탭의 동시 등록 중복 방지는 별도 범위다.
저장 후 후보 AVM·자금 분석으로 이어갈 수 있으며 금융 조건이 부족하면 보완 안내가 우선한다.

법률·세금 도구는 서버의 최근 대화를 전달하고 현재 질문의 변경 조건을 우선한다.
새 대화·다른 사용자·후보 전환은 기존 대화 격리 규칙을 따른다.
회귀는 `tests/test_concierge_complexes.py`·`test_concierge_legal_context.py`를,
과거 실제 모델 실행은 [검증 기록](../verification-history.md#historical-runs-2026-09-1213-컨시어지-단지-추천)을 참고한다.

<a id="concierge-실행-경계"></a>

### 실행 경계

- Redis에 사용자·대화 ID별 검색 조건, 후보 선택, 금융 조건, 최근 4회 대화와 직전 도구 상태를 저장한다. 마지막 요청으로부터 24시간 유지한다.
- 후보·케이스 선택을 바꾸면 이전 금융 조건과 대화 이력을 추론 입력에서 제외한다. “새 대화 시작”으로 기억한 조건을 초기화할 수 있다.
- 같은 브라우저 탭에서 새로고침하면 사용자별 sessionStorage의 대화 ID로 서버 기록을 복원한다. 완료된 최근 20회 질문·답변과 결과, 마지막 요청의 케이스·후보 선택을 복원하며 금융 조건도 이어서 사용한다. 브라우저에는 본문 대신 ID만 저장한다.
- 대화가 만료되거나 선택한 후보가 삭제되면 복원을 중단하고 새 대화를 안내한다. 서버 연결 오류는 기록을 지우지 않고 재시도를 제공한다. 계정이 바뀌면 화면 상태를 재생성하며 다른 사용자의 대화 ID는 404로 처리한다.
- 아직 답변을 받지 못한 요청의 진행 상태, 마지막 메시지 이후 바꾼 미전송 선택, 입력 중인 초안의 복원은 지원하지 않는다. 탭을 닫은 뒤나 다른 기기에서의 대화 목록 복원은 별도 기능이다.
- 저장된 후보 ID도 매 요청마다 소유권과 존재 여부를 확인한다. 모델이 후보 ID를 바꾸어 실행할 수 없다.
- 금융 조건은 범위·자료형·유한 숫자 여부를 검증한다. 필수 조건이 부족하거나 잘못되면 계산하지 않는다. null은 기존 값을 삭제하지 않는다.
- 모델 추출 봉투와 실행 조건을 분리하고 미입력 거래 유형을 매수로 가정하지 않는다.
  알려진 한글 별칭만 변환하며 지역 이름 변경 시 이전 코드를 지우고 공식 법정동으로 확인한다.
  `예산 제한 없애줘` 같은 명시적인 단독 삭제 명령만 조건을 해제한다.
  부정문·인용문·모델 단독 삭제 지시는 조건을 지우지 않는다. 모든 복합 문장의 의미 검증이 완료된 것은 아니다.
- 후보의 최신 희망가와 물건 종류를 서버에서 조회하고, `/simulation`과 공유하는 `execute_simulation`으로 계산·저장한다. LLM이 계산 결과를 재작성하지 않는다.
- 연소득·월 상환 한도가 없으면 DSR·상환 부담 검토가 남았음을 표시한다. 대출 승인 여부를 판단하지 않는다.
- 부가 투자 시나리오는 기존 계산기의 보유 3년·상승률 0%·임대수입 없음 조건을 사용하며 답변에 고지한다. 임대수입·보유기간 등 상세 시나리오 변경은 자금 분석 화면에서 진행한다.
- 비교는 `compare_case_candidates`를 재사용한다. 희망가·AVM 추정가·필요 현금·월 상환액 및 누락·갱신·위험 항목을 함께 안내하며 임의 순위를 만들지 않는다.

<a id="concierge-검증-2026-09-12"></a>

### 검증 (2026-09-12)

`tests/test_concierge_decision_tools.py`는 금융 입력 오류, 다중 턴 조건 유지, 실제 계산과 후보 저장, 금리 변경, 후보 교체·선택 해제, 삭제된 후보, 다른 사용자의 케이스·대화 접근을 검증한다. 모델 출력은 이 자동 테스트에서 고정한다.

당시 실제 모델·계산기·Redis·PostgreSQL을 사용한 Chrome 검증에서 임시 계정을 만들고 검증 후 삭제했다.
금융 조건 보완·금리 변경·후보 비교와 후보 교체를 확인했다. 희망가 6억원·현금 3억원·대출 50%·연 4%·30년
원리금균등 입력에서 필요 현금 309,600,000원, 부족액 9,600,000원, 월 상환액 1,432,246원의 표시·저장을 확인했다.
이는 계산 연결의 검증이며 금융기관 심사 또는 세무 정확성의 독립 검증은 아니다.
당시의 임시 실행 스크립트를 현재 실행 명령으로 사용하지 않는다. 현재 연결 검증은
[구조 안내](../architecture.md#repository-이번-이동-검증)를 따른다.

실제 모델이 `criteria`에 금융 필드와 선택 ID를 섞는 오류가 재현되어, 허용된 금융 필드만 이동 후 검증하고 선택 ID는 서버 선택과 일치하는 경우에만 제거하도록 보완했다. 상충하는 값은 계산하지 않는다.

실행 결과와 화면은 로컬 `evaluation-results/concierge-decision-live.json`, `concierge-decision.png`에 남는다. 이 브라우저 검증은 제한된 한국어 대화 사례이며, 모든 표현에 대한 의도·수치 추출 정확도를 보장하지 않는다. 다양한 표현의 정답셋 확대와 모델 추출 정확도 측정이 다음 개선 항목이다.

## 법률·세금 대화 기억과 복원

`/chat`의 로그인 사용자 대화를 Redis의 `law-chat:{user_id}:{conversation_id}`에 보관한다. AI 컨시어지 위젯과 별도의 기록이다. 최근 20회 완료된 질문·답변, 출처, 계산기 이름과 안내 문구를 복원하며 마지막 질문 후 24시간이 지나면 만료된다. 조회만으로 보관 기간이 연장되지는 않는다.

브라우저에는 사용자별 대화 ID만 sessionStorage로 저장한다. 같은 탭에서 새로고침하면 서버 기록을 불러온다. 계정이 바뀌면 화면 상태를 재생성한다. 만료된 기록은 새 대화로 안내하고 통신 장애는 기록을 유지한 채 재시도를 제공한다. '새 대화 시작'은 기존 대화 연결을 끊으며 서버의 이전 기록은 보관 기간 후 만료된다. 회원 탈퇴 시 해당 사용자의 법률·세금 대화 기록도 삭제한다.

최근 3회 대화가 답변 작성에 전달된다. 계산기 선택에는 이전 **사용자 발언**을 조건 보완용으로 전달하고 현재 질문의 변경 조건을 우선한다. '그 경우', '그럼' 등의 지시어로 시작하는 검색 질문에는 앞선 사용자 발언을 함께 사용한다. 과거 AI 답변을 검색어나 계산 조건으로 사용하지 않으며, 답변 생성은 새 검색·계산 결과와 기존 수치 검증을 따른다. 임의의 긴 대화나 모든 생략 표현을 완벽하게 해석한다는 의미는 아니다.

로그인 사용자의 후속 요청은 서버 기록을 사용하므로 클라이언트가 보낸 임의의 history로 저장된 조건을 덮어쓸 수 없다. 비로그인 API의 기존 일회성 답변 경로는 유지하며 비로그인 대화 복원은 제공하지 않는다.

아직 생성 중인 답변, 미전송 초안, 탭을 닫은 뒤나 다른 기기에서의 기록 복원은 지원하지 않는다. 자금·매물 비교 도구는 이 변경에 포함하지 않는다.

<a id="law-chat-검증"></a>

### 검증

- `tests/test_chat_conversations.py`: 맥락·출처 복원, 요청 history 위조 방지, 위젯과 기록 분리, 사용자 격리, 만료, 조회 시 TTL 유지, 검색·계산 라우팅 입력과 회원 탈퇴 정리.
- `scripts/verify_chat_restore_browser.cjs`: 실제 모델·법령 DB를 사용하는 Chrome 검증. 임차권등기명령 질문 → 새로고침 후 답변·원문 링크 복원 → '그 경우 어느 법원에 신청하나요?' 후속 질문을 확인했다. 새 대화에서 성인 자녀 5억 증여 질문 → 새로고침 → '배우자에게 같은 금액'으로 대상만 변경하여 계산기를 다시 실행하고, 새 대화 초기화 후 복원되지 않는 것도 확인했다.
- 결과와 화면: 로컬 `evaluation-results/chat-restore-live.json`, `evaluation-results/chat-restore.png`. 임시 검증 계정은 실행 후 삭제한다. 한정된 대화 흐름 검증이며 법률·세무 정확성 전체를 보증하는 평가가 아니다.
