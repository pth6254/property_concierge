# 챗봇 아파트 단지 추천 연결

2026-09-12: 기존에 비활성화되어 있던 `select_properties`를 실거래 단지 추천 서비스에 연결했다.

- 시·군·구 또는 법정동, 아파트, 매매 조건이 필요하다. 없는 조건은 보완 입력으로 안내하고 시·도만 지정하면 구나 동을 묻는다.
- 기존 대화의 지역·예산·최소 면적을 유지한다. 최소 면적은 거래 단위 하한으로 적용한다. 챗봇의 예산 상한은 시점수정 단지 평균 가격에 엄격하게 적용하며, 기존 탐색 화면의 10% 여유 예산과 구분한다.
- 최근 12개월 해제 제외 실거래를 기반으로 최대 5개 단지를 안내한다. 조회·집계 결과를 결정론적 문장으로 표시하므로 답변 작성용 LLM을 추가 호출하지 않는다.
- 실제 호가나 판매 중인 매물 조회가 아니다.

## 2026-09-13 후보 저장과 대화 맥락 개선

추천 답변의 단지 카드에서 검토 주소와 실제 전용면적을 확인하고 ‘후보 저장·선택’을 누르면 현재 케이스에 저장한다. 케이스가 없으면 생성한다. 면적은 평균값으로 자동 저장하지 않으며, 희망가는 사용자가 확인한 값만 만원 단위로 입력한다. 희망가를 생략하면 자금 분석에 필요한 보완 항목으로 안내한다.

저장된 후보는 챗봇 선택란에 즉시 반영된다. ‘선택 후보 AVM 실행’과 ‘선택 후보 자금 분석’ 버튼으로 후속 도구를 호출한다. 동일 케이스의 이름·주소·면적·아파트 유형이 일치하면 기존 후보를 선택하며 가격을 덮어쓰지 않는다. 이는 해당 화면의 순차 재클릭 방지이며, 여러 탭에서 동시에 저장할 때 DB 차원의 중복 방지를 보장하는 기능은 아니다.

컨시어지 법률·세금 도구에는 서버가 보관한 최근 대화를 전달한다. 세금 라우팅은 이전 사용자 발언으로 생략 조건을 보완하고 현재 발언의 변경 조건을 우선한다. RAG 검색과 수치 가드는 기존 법률·세금 서비스 경로를 사용한다. 새 대화·다른 사용자·후보 전환 시 기존 대화 격리 규칙을 유지한다.

회귀 검증: `tests/test_concierge_legal_context.py`에서 직전 질문 전달, 새 대화 초기화, 다른 사용자 대화 격리를 확인했다. 프론트엔드는 타입 검사·린트·빌드를 통과했고 전체 백엔드는 894개 통과했다.

실제 브라우저에서 추천 → 후보 저장·선택 → 재저장 시 기존 후보 선택 → 자금 분석의 금융 조건 보완 안내 → 저장 후보의 AVM 완료를 확인했다. 법률·세금 질문은 ‘성인 자녀에게 현금 5억 증여’ 다음 ‘같은 금액을 배우자에게’로 이어 물어 배우자 조건의 답변을 확인했다. 검증 스크립트: `scripts/verify_concierge_candidate_flow.cjs`(Playwright·Chrome 필요, 임시 계정 생성 및 종료 시 삭제). 이 검증의 자금 분석 범위는 후보 전달과 미입력 금융 조건 안내이며 새로 저장한 후보에 대한 완전한 금융 계산 실행까지 의미하지 않는다.

검증: 전체 백엔드 893개, 고정 입력 평가 33/33, 프론트엔드 타입 검사·린트·빌드 통과. `tests/test_concierge_complexes.py`는 예산 상한, 최소 면적, 후속 조건 유지, 미지원·불완전 입력, 답변 모델 재호출 방지를 검증한다.

실제 브라우저에서 ‘역삼동 8억 이하 아파트 매매 동네’ 후 ‘그럼 구체적으로 아파트 단지 추천해줘’를 질문해 역삼동 단지 5개와 예산 유지·화면 표시를 확인했다. 해당 실행의 동네 답변은 약 9초, 후속 단지 추천은 약 7초였다. 단일 실행 측정으로 일반적인 응답 시간 보장은 아니다. 로컬 검증 이미지: `evaluation-results/chat-complexes.png`.
