# 작업 기록 (PPT 작성용 사실 정리)

과제의 "AI 활용 내역"은 무엇을 AI가 했고 무엇을 본인이 판단했는지 구분해야 합니다.
아래는 2026-10-11 AI 코딩 도구(Claude Code)와 진행한 작업의 **사실 기록**입니다. 본인의 판단·결정은 PPT에 직접 채워 주세요.

## 진행 순서와 확인한 사실

1. **데이터 점검에서 결함 발견**: 기존에 저장해 둔 연립다세대 거래 6,155건 중 지번이 있는 거래가 366건(약 6%)뿐이었다.
   지번 열을 나중에 추가하면서 이전 행이 채워지지 않은 것이 원인이었다. 빌라의 가장 강한 근거인 "같은 건물 거래"를 쓸 수 없는 상태였다.
   → 3개 구 2023-10~2026-10을 다시 수집했다(111개월, 15,637건, 실패 0).
2. **원천 필드 확인**: 응답 원문을 직접 확인해 대지권면적(`landAr`)과 연립/다세대 구분(`houseType`)이 있음을 확인하고 수집 대상에 넣었다.
3. **같은 건물 근거 비율 측정**: 최근 12개월 거래 중 같은 건물의 이전 24개월 거래가 있는 비율은 강서 57%·관악 52%·강남 63%였다.
   → 같은 건물(L1)만으로는 절반 정도만 덮으므로 L2(같은 동 유사)·통계 보정 단계를 설계했다.
4. **직거래 확인**: 강서·관악에서 직거래의 ㎡당 중앙값이 중개거래보다 높았다(신축 분양 직거래 추정). 직거래를 제외하지 않고 변수로 넣었다.
5. **방식 비교**: 같은 시간 분할에서 비교사례만 / CatBoost만 / 혼합형을 비교했고 두 기간 모두 혼합형이 가장 낮은 오차였다(README 표).
6. **조정과 재확인**: 첫 실행 후 평가 구간의 오차 큰 사례를 본 뒤 ① 같은 본번 블록 변수 ② 학습 구간 이상치 제외 ③ 손실 함수 선택을 추가했다.
   이 선택은 검증 구간 지표로만 했고, 조정에 쓰지 않은 앞선 기간(2026-04~06)으로 다시 확인했다.
7. **구간 보정 수정**: 앞선 기간에서 80% 명목 구간의 실제 적중이 72~77%로 낮았다. 85% 명목으로 넓혀 두 기간 실제 적중 81~83%를 확인했다.
   L3(근거 없음)는 검증 표본이 26건이라 평균값을 빌리면 근거가 약한데도 신뢰도가 높아지므로, 더 보수적인 L2 값을 빌리도록 바꿨다.
8. **전용면적 대체값 위험 확인**: 키 없이 실행했을 때 같은 건물 면적 중앙값(20.58㎡)을 썼지만 그 건물 최근 거래는 42.35㎡였다.
   건축물대장 전유부 조회로 실제 26.04㎡를 받아 확인했다. 대체값을 쓸 때는 구간을 넓히고 신뢰도를 낮추며 `basis`에 밝힌다.

## AI 출력에서 잡아낸 오류 (사실)

- 쉘 heredoc 인코딩·이스케이프 문제로 스크립트가 일부 적용되지 않은 경우가 있었고, 결과 파일을 다시 읽어 확인한 뒤 수정했다.
- 평가 지표를 문서에 옮길 때 최신 결과 파일(`validation/*.json`)과 대조해 일치 여부를 확인했다.

## 본인이 채울 항목

- 연립 포함 여부, 85% 명목 구간 채택, 직거래 처리 방식 등 최종 결정의 근거(본인 판단)
- AI 없이 했을 때 예상 소요 시간
- 예시 산출 3건(`input_sample.csv`·`output_sample.csv`의 1~3번 또는 새 물건)의 해석

## 저장소 이동 (2026-10-12)

- 바탕화면 별도 폴더에서 Property Concierge 저장소 `services/intelligence/avm/`으로 옮겼다. 모델 등록표 복사본을 지우고 서비스 원본을 쓰며, 제출 묶음은 `package.py`로 만든다.

## 모델 교체 구조 (추가)

- 가격 모델을 서비스와 같은 등록표(`backend/valuation/models`, 제출 묶음에서는 `rh_avm/models`)로 분리했다. `train.py --model 이름`으로 바꾸면 `model/model.json`(manifest)이 바뀌고 `predict.py`는 코드 수정 없이 그 모델을 읽는다.
- 같은 분할(2026-07~09)에서 `ridge` 17.2%, `catboost` 15.4%(과제 권역 MAPE)로 비교했고, 교체 → 산출 → 되돌리기를 실제로 실행해 확인했다.
- 이 구조 변경으로 CatBoost 조기 종료가 학습 이상치를 뺀 검증 자료로 바뀌어 2026-07~09 중앙값 오차가 10.0%→10.5%로 달라졌다(MAPE 15.6% 동일). README 표는 변경 후 값이다.
