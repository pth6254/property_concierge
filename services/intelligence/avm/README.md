# 연립·다세대 AI 시세 모델 (스카이키 과제)

권역(서울 강서구 화곡동·강남구·관악구) 안의 지번·층·호를 넣으면 매매 시세·하한·상한·신뢰도·근거를 내는 모델입니다.
**거래사례비교법을 주된 방법**으로 하고, 비교사례를 변수로 넣은 **CatBoost로 층·준공연도·대지권비율·시점을 보정**합니다.
감정평가가 아닌 AVM 참고 시세입니다.

## 설치·실행

Python 3.11 이상.

```bash
pip install -r requirements.txt
export MOLIT_API_KEY="공공데이터포털 일반 인증키"   # Windows PowerShell: $env:MOLIT_API_KEY="..."
python predict.py --input input.csv --output output.csv            # 기준일: 오늘(한국 시간)
python predict.py --input input.csv --output output.csv --as-of 2026-10-24
```

- 학습된 모델(`model/`)과 수집 데이터(`data/`)가 포함되어 있어 바로 실행됩니다. 20건 기준 수 초가 걸립니다(건축물대장 조회 포함 시 건당 1~2회 API 호출).
- `MOLIT_API_KEY`가 없어도 실행됩니다. 이때는 건축물대장 조회를 건너뛰고 그 사실을 `basis`에 적은 뒤 다른 근거로 추정을 계속합니다.
- 키 발급: [공공데이터포털](https://www.data.go.kr)에서 아래 두 API를 활용 신청하면 같은 일반 인증키로 호출됩니다.
  - 국토교통부_연립다세대 매매 실거래가 자료 (`RTMSDataSvcRHTrade`) — 데이터 재수집용
  - 국토교통부_건축HUB_건축물대장정보 서비스 (`BldRgstHubService`) — 전용면적·사용승인일 보완용

데이터를 새로 수집하고 다시 학습하려면:

```bash
python collect.py --from 202310 --to 202610   # data/rh_trades.csv 갱신
python train.py                               # model/ 갱신 (마지막 3개 완료월로 검증·보정)
python validate.py --train-start 202410 --validation-start 202605 --test-start 202607 --test-end 202609
```

## 입출력

입력 `input.csv`: `id, sigungu, dong, jibun, floor, ho, area_m2` (`ho`·`area_m2`는 비어 있을 수 있음)
출력 `output.csv`: `id, price_est, price_low, price_high, confidence, basis, status`

| 상황 | 처리 |
|---|---|
| 전용면적 입력 | 입력값 사용 |
| 전용면적 없음 | 건축물대장 전유부(지번+호)의 전유 면적 → 실패 시 같은 건물 실거래 면적 중앙값으로 추정(구간 ±10% 확대, 신뢰도 ×0.7, `basis`에 명시) → 그것도 없으면 `fail` |
| 같은 건물 실거래 없음 | 건축물대장 표제부로 사용승인 연도·주용도 확인. 주용도가 공동주택이 아니면(근생빌라 등) 신뢰도 하향 |
| 권역 밖(강서구 화곡동 외, 다른 구) | `fail: 사유` |
| 층 없음 | 호(예: 301 → 3층, B01 → 지하 1층)에서 추정 |


## 사용 데이터

| 데이터 | 출처 | 범위·건수 | 용도 |
|---|---|---|---|
| 연립다세대 매매 실거래 | 국토교통부 실거래가 공개시스템(공공데이터포털 API `RTMSDataSvcRHTrade`) | 강서·관악·강남, 거래월 2023-10~2026-10, 15,637건(해제 854건 포함, 2026-10-11 수집) | 비교사례·학습·검증 |
| 건축물대장 표제부·전유부 | 국토교통부 건축HUB(`BldRgstHubService`) | 실행 중 필요한 건만 조회 | 전용면적·사용승인 연도·주용도 보완 |
| 법정동 코드 | 행정안전부 법정동코드 | 3개 구 30개 동 | 건축물대장 조회용 코드 변환 |

- 실거래 원천에는 연립·다세대 구분(`houseType`)이 있으며 **둘 다 포함**합니다(연립 1,572건·다세대 14,028건·구분 미기재 37건). 법정 기준(4층 이하, 바닥면적 660㎡ 경계)만 다르고 같은 원천·같은 가격 요인으로 설명되므로 한 모델에 구분 변수로 넣었습니다.
- 학습에는 강서구 전체 거래를 쓰고(인접 동의 시세 정보), 산출은 과제 권역(화곡동)으로 제한합니다.
- 하우스머치 등 상용 시세 서비스의 결과는 입력·학습에 쓰지 않았습니다. 개인정보(소유자명 등)는 수집하지 않습니다.

## 모델 요약

1. **정리**: 해제 거래, 날짜·면적·가격·지번 누락, 같은 건물·날짜·층·면적·가격의 중복 신고를 제외합니다.
2. **시점 지수**: 구별 ㎡당 가격(로그)의 최근 3개월 중앙값. 기준 월은 쓰지 않고 그 전달까지만 씁니다.
3. **비교사례 근거 단계** (항상 기준일 **이전** 거래만, 대상 자신 제외)
   - L1 같은 건물(법정동+지번) 최근 24개월 → L1a(3건 이상)/L1b(1~2건)
   - L2 같은 동, 준공 ±5년, 전용면적 ±20%, 최근 12개월 3건 이상
   - L3 근거 없음 / 보조: 같은 본번 블록(예: 593-xx) 최근 12개월
4. **CatBoost 보정**: 타깃은 ㎡당 가격 로그. 변수는 비교사례 추정값·건수·면적 차이·경과일, 블록 중앙값, 층, 전용면적, 경과연수, 대지권비율, 구·동·연립/다세대, 시점, 거래 유형.
   - 학습 구간에서만 비교사례 대비 로그 0.5 이상 벗어난 거래(지분·특수관계 추정)를 뺍니다.
   - 블라인드 입력에는 거래 유형이 없으므로 산출은 중개거래로 가정합니다.
5. **구간·신뢰도**: 마지막 3개 완료월(검증)의 잔차로 근거 버킷별 7.5%~92.5% 분위수를 하한·상한으로, ±10% 적중률을 신뢰도로 씁니다.
   - 이전 기간 점검에서 80% 명목 구간의 실제 적중이 72~77%로 낮아 85% 명목으로 넓혔습니다.
   - 검증 표본 30건 미만 버킷은 상위 버킷 값을 쓰며, 근거가 가장 약한 L3는 L2 값을 빌립니다.

## 자체 검증 (시간 분할 홀드아웃)

`validate.py`는 학습 < 검증 < 평가로 나누고, 반복 수·구간·신뢰도를 검증으로만 정한 뒤 평가 구간에서 측정합니다.

| 평가 기간 | 표본 (과제 권역) | 혼합형 MAPE / 중앙값 / ±10% | 과제 권역 MAPE | 비교사례만 MAPE | 구간 적중 (과제 권역) | 과제 권역 20건 무작위 MAPE 중앙값 (p10~p90) |
|---|---|---|---|---|---|---|
| 2026-07~09 (검증 05~06) | 1,269 (1,050) | 15.6% / 10.6% / 47.8% | 15.4% | 17.8% | 83.0% | 15.0% (10.9~20.7%) |
| 2026-04~06 (검증 02~03) | 1,789 (1,514) | 16.4% / 10.9% / 46.7% | 16.4% | 19.8% | 81.3% | 16.2% (11.7~21.9%) |

근거 버킷별 신뢰도(검증)와 평가 구간 실제 ±10% 적중률:

| 버킷 | 2026-07~09 | 2026-04~06 |
|---|---|---|
| L1a 같은 건물 3건 이상 | 0.590 → 0.601 | 0.623 → 0.600 |
| L1b 같은 건물 1~2건 | 0.458 → 0.516 | 0.505 → 0.480 |
| L2 같은 동 유사 | 0.406 → 0.385 | 0.424 → 0.391 |
| L3 근거 없음 | 0.406 → 0.192 (26건) | 0.424 → 0.542 (59건) |

L3는 표본이 적어 판단하기 어렵습니다. 오차가 가장 큰 사례는 실거래가가 추정의 절반 이하인 거래이며, 원자료에 지분·특수관계 거래를 구분하는 필드가 없습니다.
기간별 상세(지역별·버킷별 오차, 오차 큰 사례 10건)는 `validation/holdout_*.json`에 있습니다.

## 가격 모델 교체

가격 모델은 `rh_avm/models`의 등록표에서 이름으로 고릅니다. 학습·보정·검증·산출 코드는 공통 인터페이스(`PriceModel`: `fit`·`predict`·`predict_probe`·저장/읽기)만 사용하며,
`model/model.json`(manifest)에 모델 이름·설정·학습 정보·파일 해시·보정값이 기록되어 `predict.py`가 같은 구현으로 읽습니다. 파일이 manifest와 다르면 읽기를 거부합니다.

```bash
python validate.py --train-start 202410 --validation-start 202605 --test-start 202607 --test-end 202609 --model ridge   # 같은 분할로 비교
python train.py --model ridge     # 교체: model/이 ridge로 바뀌고 predict.py가 그대로 사용
python train.py                   # 기본(catboost)으로 되돌리기
```

| 등록 모델 | 설명 | 2026-07~09 혼합 MAPE (과제 권역) |
|---|---|---|
| `catboost` (기본) | 비교사례 변수를 넣은 그래디언트 부스팅 | 15.4% |
| `ridge` | numpy 릿지 회귀(외부 ML 라이브러리 불필요) | 17.2% |
| `comparables` | ML 없이 비교사례 값 → 블록 → 지수 순 대체 | 기준선 |

새 모델은 `PriceModel`을 상속해 `@register("이름")`을 붙인 파일을 `rh_avm/models/`에 추가하고 `_load_builtin`에 import를 더하면 됩니다.
입력은 pandas DataFrame, 출력은 ㎡당 가격의 자연로그이며 숫자 결측(NaN)을 스스로 처리해야 합니다. 교체 전에는 같은 분할로 `validate.py`를 실행해 비교하세요.

## 저장소 위치와 제출 묶음

원본은 Property Concierge 저장소의 `services/intelligence/avm/`에 있습니다. 저장소 안에서는 `rh_avm/models` 폴더가 없고,
가격 모델 등록표를 서비스 원본(`services/intelligence/backend/valuation/models`)에서 가져옵니다. 서비스 평가와 과제 산출이 같은 모델 구현을 쓰게 하기 위해서입니다.
제출용 단독 실행 묶음은 `python package.py`로 만들며, 이때 등록표를 `rh_avm/models`로 복사해 넣습니다(`dist/avm/`, `dist/avm.zip`, 작업 기록 `NOTES.md` 제외).

## 한계

- 건물 좌표·역세권·학군 등 위치 변수를 쓰지 않았습니다(본번 블록으로 근접만 대신). 같은 건물·같은 동 근거가 약한 L2·L3에서 오차가 큽니다.
- 공동주택 공시가격, 연립다세대 전월세(전세가율)는 아직 쓰지 않았습니다.
- 실거래 신고 지연(최대 30일)으로 최근 거래가 일부 빠질 수 있습니다.
- 같은 건물의 호별 향·구조 차이, 위반건축물 여부는 반영하지 않았습니다(표제부 주용도만 확인).
